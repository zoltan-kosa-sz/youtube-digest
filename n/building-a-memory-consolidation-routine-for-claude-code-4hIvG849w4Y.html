Building a memory-consolidation routine for Claude Code

Austin Marchese / 2026-09-13 / Watch

Use

  1. Run a scheduled memory clean-up. A recurring job reads your recent sessions and proposes edits to your memory and CLAUDE.md files, so you stop giving the same correction twice.
  2. Give review and apply their own slots. Run the analysis one day and apply the approved fixes the next, or a known problem sits unfixed until the next run.
  3. Move folder-specific instructions into that folder. Rules that load only where they apply keep unrelated context out of the window.

Bottom line

Claude's memory problem isn't that it forgets — it's that nothing decides what's worth keeping. People consolidate the day's memories while asleep; Claude starts every session cold, so the fix is a scheduled job that rereads past sessions and rewrites the memory files itself.

Key ideas

  • The missing step is consolidation, not storage. Karpathy's framing: sleep turns a day's short-term context into long-term changes in the brain. Models have no equivalent and restart from nothing.
  • Three layers hold your context and do different jobs. The live session (gone when it ends), memory files (facts Claude captured on its own), and CLAUDE.md (rules you deliberately wrote down). The last two load at the start of every session.
  • Build each step as a separate skill, then have one skill call them. Analysing sessions, improving memory and sending the result are each useful alone; the "dream" skill only orchestrates.
  • Your raw session history holds more than the memory file does. Claude Code saves conversations locally; memory keeps only what it judged important at the time, so rereading the raw record surfaces patterns it skipped.
  • A human still signs off. The job splits changes into what it applied itself and what you must decide — otherwise an automated rewrite quietly drifts your instructions.
  • Anthropic already ships exactly this. Its Dreams feature rereads past sessions and rebuilds the memory store; the video's contribution is a hand-rolled version for people who can't access it.

Reality check

  • Mixed"Karpathy joined Anthropic to fix Claude's memory." He did join, in May 2026, but onto the pre-training team under Nick Joseph. Nothing announced ties him to memory work; the video's whole framing rests on a link that was never stated.
  • SupportedDreams works as described. Anthropic's API docs confirm a dream reads a memory store plus up to 100 past session transcripts, merges duplicates, replaces contradicted entries, and accepts an instructions field to steer it.
  • Mixed"Dreams is enterprise-only." It's a gated research preview on Managed Agents, billed at normal API token rates, on Opus 4.7 and Sonnet 4.6. Restricted by preview access, not by company size — "email me if you're an enterprise" is a sales line, not the access rule.
  • MixedThe pushback on Boris Cherny. The quote is real (YC Startup School 2026), but the video narrows it to coding help. Cherny aimed it at "people who aren't building agentic products but are using Claude Code" — this video's exact audience — and Anthropic cut 80% of Claude Code's system prompt for Opus 5.
  • Sales motive — The build routes through the presenter's own plugin, with a sponsor read and a giveaway attached. The underlying idea stands on its own; the tooling recommendation doesn't.
