Turning Claude design output into maintainable code

Firecrawl / 2026-09-12 / Watch

Use

  1. When using Claude Code's `/design` skill, don't let Claude generate the site code directly from the artifact — prompt it to use the Firecrawl developer index skill first (reads current framework docs) so it builds proper components/routes in a real framework (e.g. Next.js) instead of raw HTML/CSS/vanilla JS.
  2. To get a reusable design system without Claude Design proper: scrape a reference site with Firecrawl (`format: branding + screenshots`) to pull logo, colors, fonts, and components, then use Firecrawl's website design clone skill to generate a `design.md` Claude Code can build from.
  3. For inspiration-driven design work, feed Claude a reference URL + an image source (Unsplash/Lummi API) plus the instruction to study the site via Firecrawl before designing — produces noticeably better output than a cold prompt.

Bottom line

Claude Code's new `/design` skill makes good-looking artboards but bad, unmaintainable code and no portable design system; Firecrawl's developer-index and site-scraping/clone skills patch both gaps — better generated code and a transferable design system built from any reference site.

Key ideas

  • Claude Code's `/design` skill produces vanilla HTML/CSS/JS with poor patterns (IIFEs, `var`, non-arrow callbacks) — hard to maintain or extend, unlike a framework-based build.
  • Firecrawl's developer index gives the coding agent live, indexed framework docs (Tailwind 4, PostCSS, Next.js app router/fonts) during code generation, which is what turns the output into structured components and routes instead of one messy script.
  • Claude's own `/design-sync` skill can build a design system, but only for use inside Claude Design — it doesn't carry over to Claude Code's `/design` skill, creating a gap Firecrawl fills via scraping.
  • Firecrawl's scrape endpoint extracts brand assets (logo, favicon, OG image, colors, typography, components) from any URL, letting you build a "design system" from a competitor or inspiration site rather than from scratch.
  • The `/design` skill in Claude Code is more limited than Claude Design proper: no templates, no on-artboard comments to Claude, no layout drag-and-drop persistence, no fullscreen/new-tab view — reflects its "research preview" status.

Reality check

  • SupportedFirecrawl's developer index covers 70M+ developer artifacts (docs, READMEs, issues, PRs) — confirmed on Firecrawl's own site and independent coverage; it's a real, currently-shipping product feature, not a made-up number.
  • SupportedClaude Code's `/design` command is a real, currently-in-research-preview feature (confirmed via Anthropic-adjacent coverage), matching the video's description of artboards, desktop/mobile views, and limited functionality vs. Claude Design.
  • Mixed"Built the whole site in under an hour, no other libraries needed" — this is the presenter's own unverified claim in a video promoting Firecrawl (with a signup discount code at the end), so treat the speed/simplicity framing as a sales pitch rather than a measured result; your own mileage on iteration count will vary.
