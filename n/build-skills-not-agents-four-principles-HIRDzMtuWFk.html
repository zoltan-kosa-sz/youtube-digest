Build skills, not agents — four principles

Ai Engineer / 2026-09-20 / Watch

Use

  1. Save working code inside skills — Stop having Claude rewrite the same Python script or template every run. Extract proven solutions into tool files and reference them from the skill, so Claude reuses rather than rediscovers.
  2. Write unambiguous skill descriptions — Use clear YAML frontmatter that says exactly what the skill does and when to use it. Audit descriptions so Claude picks the right skill, not a similar-sounding one.
  3. Build verification into the workflow — Add checks before Claude returns work to you (render slides as images to catch formatting, verify sources match claims, run sub-agent reviews). Let it fix its own errors rather than you catching them.

Bottom line

Instead of rebuilding agents for each job, design general-purpose skills with clear descriptions, reusable code, and built-in verification loops so the agent improves itself with each run. Anthropic engineers moved from task-specific agents to modular skills because a well-designed skill teaches the agent how you work, while a one-off agent forgets.

Key ideas

  • Save proven code as a tool for the agent's future self — When Claude solves a problem well (a script that styles slides, a rendering template), extract it and store it in the skill folder. Future runs call the proven version instead of reinventing it, which saves tokens and keeps output consistent.0:31
  • Progressive disclosure: load only what the task needs — Claude starts with just the skill name and description in the system prompt. When your prompt matches a skill's description, Claude reads the full skill.md. Larger files and scripts stay in the folder until they're actually needed. This cuts context bloat and avoids the confusion of overlapping skills.3:05
  • Clear, specific descriptions trigger the right skill — Vague descriptions ("help with content" vs. "create marketing assets") make Claude guess. Stronger: "Creates LinkedIn carousels from a topic, transcript, or outline. Use this when the user asks for a carousel, slides, or LinkedIn post." Include the words a real person would use.3:35
  • Turn each correction into a durable rule — When Claude makes the same mistake twice, don't just fix it in the moment—update the skill. If it's a process issue, update the instructions. If it's missing context, add reference files. If it's a recurring error, add an explicit rule. The skill becomes a living record of how you want the job done.5:07
  • Verify work before it reaches you — Build checks into the skill: render slides as images and inspect them; match sources to claims before returning; have multiple agent personas review subjective work. Define acceptance criteria, create a first version, inspect it, fix issues, run another pass, then return. Claude should make 4–6 passes before you see draft one.6:38
  • Test skills across compatible agents — Skills are an open format. If a skill works only with one model or agent, it's hiding assumptions. Test with another compatible agent (CodeX, Hermes). If it falls apart, tighten instructions and examples. A portable skill is a teachable one.6:08
